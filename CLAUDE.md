# Контекст проекта Qulay shahar

Файл для того, кто вернётся к проекту через месяц — включая ИИ-ассистента
в новой сессии. Здесь то, что не очевидно из кода: зачем сделано именно
так и где закопаны грабли.

## Что это

Краудсорсинговая карта городской доступности Ташкента. Жители через
Telegram-бота присылают геолокацию и фото мест, где нет условий для
проезда: нет пандуса, разбит тротуар, перекрыт проход. После модерации
точка появляется на публичной карте.

Цель — не карта сама по себе, а разговор с городскими службами на
основе данных. Отсюда два следствия в дизайне: точки не исчезают
(история проблемы важнее свежести), и есть статус «устранено» —
чтобы показывать не только претензии, но и результат.

- Боевой адрес: https://qulayshahar.uz
- Репозиторий: https://github.com/SeanKOFF/pandus

## Стек

Django 6 (сайт + админка модерации + бот одной командой), PostgreSQL,
aiogram 3, Leaflet + тайлы OpenStreetMap, gunicorn, Docker Compose.
Интерфейс на русском и узбекском.

## Решения, которые легко случайно сломать

**Жизненный цикл заявки:** `pending → published → resolved / rejected`.
Опубликованная точка живёт бессрочно, пока статус не сменят руками.
Ничего не удаляется, `rejected` тоже остаётся в базе.

**Отдельной «таблицы решённых» нет.** Есть `ReportStatusHistory`, куда
`Report.save()` пишет каждую смену статуса. Отчёт об устранённом за
период — это фильтр по ней. Не заводите вторую таблицу.

**Категории — данные, не код.** Таблица с `label_ru` / `label_uz` и
методом `label()`. Новая категория добавляется через админку и сразу
появляется в кнопках бота и легенде карты, без деплоя.

**API отдаёт только то, что перечислено явно** в `_serialize()`.
Ни автора, ни модератора, ни `moderation_notes`. Не заменяйте на
сериализацию модели целиком — утечёт.

**Фото не имеют публичных URL.** В базе лежит `photo_ref` —
идентификатор в хранилище. Наружу только через `/media/<id>/`, где
проверяется статус: снимок заявки на модерации виден лишь сотруднику.

**EXIF вырезается при загрузке** (`images.py`). Вместе с ним уходят
GPS-координаты съёмки, которые модератор глазами не увидел бы. Не
добавляйте путь, где фото сохраняется в обход `normalize()`.

**Бот не использует gettext.** aiogram обрабатывает сообщения
асинхронно в одном потоке, а активный язык Django потоко-локальный —
при одновременных диалогах он бы протекал между пользователями. Язык
передаётся явно: из `Reporter.language` и из состояния FSM. Сайт при
этом на обычном gettext — это осознанная асимметрия.

**Атрибуция OpenStreetMap обязательна.** Подпись «Leaflet» убрана
(его лицензия упоминания не требует), ссылка на OSM оставлена: данные
под ODbL, плюс правила бесплатного тайлового сервера. Убирать нельзя.

**`proxy_pass` в nginx — только через переменную с `resolver`.**
Прямое имя контейнера в `proxy_pass` не даст nginx стартовать, когда
контейнер недоступен, и уронит соседние сайты на том же сервере.

## Развёртывание

Всё, что привязывает проект к серверу, лежит в `.env`. Кода переезд
не касается.

Режим выбирается переменной `COMPOSE_FILE`:

- `docker-compose.yml:docker-compose.shared-nginx.yml` — за чужим
  nginx, портов наружу не публикует (так работает сейчас)
- `docker-compose.yml:docker-compose.caddy.yml` — автономно, свой
  Caddy получает TLS сам

Команды в обоих случаях одинаковые: `docker compose up -d --build`.

**Текущий сервер:** Hetzner, рядом с svetanet.uz / chiroqyoq.uz /
gazyoq.uz за общим nginx в контейнере `sveton-frontend-1`. Проект
изолирован: свой PostgreSQL, свои тома, своя сеть. Единственная точка
соприкосновения — один файл в `conf.d` того nginx, подключённый одной
строкой в его `docker-compose.yml`.

Сертификаты — certbot в режиме standalone, с хуками остановки
контейнера nginx на время продления.

Подробности: `docs/deployment-sveton.md`, переезд — `docs/migration.md`.

## Порядок работы

Правки делаются локально и пушатся в GitHub. **На сервере только
`git pull`** — локальные правки там создают расхождение, которое
мешает обновляться.

Локальный запуск без PostgreSQL:

```bash
USE_SQLITE=1 python manage.py runserver
USE_SQLITE=1 python manage.py bot      # в отдельной вкладке
```

После правки текстов интерфейса:

```bash
python manage.py makemessages -l uz
# перевести .po, снять пометки fuzzy — иначе строка не попадёт в .mo
python manage.py compilemessages -l uz
```

## Что не сделано

- **Юридическая проверка.** Публикация фотографий городской среды,
  собранных от жителей, регулируется законодательством о персональных
  данных. Технически сделано что можно: премодерация, вырезание
  метаданных, автор не публикуется. Юридическая сторона не выяснена.
- **Уведомления автору** о публикации и устранении. Возвращают людей,
  превращают разовое сообщение в ощущение, что услышали.
- **Страница статистики** для разговора с городом.
- **`OneDriveStorage`** — интерфейс готов, реализация заглушка.
  Понадобится, если проект переедет на PaaS с эфемерным диском.
- **`scripts/backup.sh`**: архив фотографий создаётся от root, из-за
  чего ротация от имени пользователя его не удалит. Решение —
  `--user "$(id -u):$(id -g)"` в `docker run`.
- Узбекские тексты писал не носитель языка — формулировки стоит
  вычитать.

## Не техническое, но важное

Карта сама себя городу не покажет. К моменту разговора с хокимиятом
нужны данные: сплошное покрытие одного района убедительнее, чем
разрозненные точки по всему Ташкенту, и его можно принести конкретному
районному хокимияту. Организации инвалидов и урбанистические сообщества
дадут и данные, и вес в разговоре.
