# Переезд на другой сервер

Проект специально собран так, чтобы смена хостинга не требовала правок
кода. Всё, что привязано к конкретному серверу, лежит в одном файле `.env`.

## Что где привязано

| Привязка | Где задаётся | Что делать при переезде |
|---|---|---|
| Способ выхода наружу | `COMPOSE_FILE` в `.env` | выбрать другую надстройку |
| Домен | `DOMAIN`, `DJANGO_ALLOWED_HOSTS` | вписать новый |
| Сеть чужого nginx | `PROXY_NETWORK` | вписать новую или убрать |
| Имена контейнеров | `COMPOSE_PROJECT_NAME` | обычно не меняется |
| Данные | тома `*_pgdata`, `*_photos` | перенести бэкапом |

Кода, `docker-compose.yml` и `Dockerfile` переезд не касается.

## Два режима работы

Выбираются переменной `COMPOSE_FILE` в `.env`, команды при этом всегда
одинаковые — `docker compose up -d --build`.

**За чужим nginx** — когда порты 80/443 на сервере уже заняты другим
проектом:

```
COMPOSE_FILE=docker-compose.yml:docker-compose.shared-nginx.yml
PROXY_NETWORK=имя_сети_того_nginx
```

**Автономно** — на чистом сервере, свой Caddy получает TLS сам:

```
COMPOSE_FILE=docker-compose.yml:docker-compose.caddy.yml
```

Переключение между режимами — правка одной строки и перезапуск.

## Переезд: пошагово

### На старом сервере

```bash
cd /путь/к/pandus
./scripts/backup.sh
```

Получите два файла в `/var/backups/pandus/`: дамп базы и архив
фотографий. Скопируйте их на новый сервер и сохраните `.env` — в нём
секретный ключ Django и пароль базы.

```bash
scp /var/backups/pandus/db_*.sql.gz    deploy@НОВЫЙ_СЕРВЕР:~/
scp /var/backups/pandus/photos_*.tar.gz deploy@НОВЫЙ_СЕРВЕР:~/
scp .env                                deploy@НОВЫЙ_СЕРВЕР:~/pandus.env
```

### На новом сервере

```bash
curl -fsSL https://get.docker.com | sh     # если docker ещё не стоит
git clone https://github.com/SeanKOFF/pandus.git
cd pandus
cp ~/pandus.env .env
chmod 600 .env
nano .env      # поправить DOMAIN, DJANGO_ALLOWED_HOSTS, COMPOSE_FILE, PROXY_NETWORK
```

`DJANGO_SECRET_KEY` и `DB_PASSWORD` **оставьте прежними** — иначе база из
дампа не откроется, а сессии модераторов слетят.

```bash
docker compose up -d --build
./scripts/restore.sh ~/db_*.sql.gz ~/photos_*.tar.gz
```

Скрипт остановит приложение, зальёт базу и фотографии, поднимет всё
обратно.

### Домен

Переключите A-запись на новый IP. Пока DNS расходится, старый сервер
лучше не выключать.

Если новый сервер автономный — Caddy получит сертификат сам, ничего
делать не нужно. Если за чужим nginx — выпустите сертификат и
сгенерируйте конфиг (см. ниже).

### Проверка и выключение старого

```bash
docker compose ps
docker compose logs -f
```

Убедитесь, что карта открывается, точки на месте, фотографии
показываются, бот отвечает на `/start`.

Бот Telegram работает опросом (polling), поэтому **два запущенных бота
с одним токеном будут конфликтовать**. Перед запуском на новом сервере
остановите старый:

```bash
# на старом сервере
docker compose stop bot
```

Старый сервер держите неделю на случай отката, потом:

```bash
docker compose down -v
```

## Генерация конфига nginx

Файл `deploy/nginx-site.conf.template` содержит плейсхолдеры вместо
домена и имени контейнера. Готовый конфиг создаётся из `.env`:

```bash
./deploy/render-nginx-conf.sh > /путь/к/nginx/conf.d/pandus.conf
```

Правьте `.env`, не шаблон. Подставляются только `DOMAIN` и
`PROJECT_PREFIX`, переменные nginx (`$host`, `$scheme`) остаются
нетронутыми.

## Переезд на PaaS вместо VPS

Render, Railway, Fly.io и им подобные запускают контейнер из
`Dockerfile`, который здесь уже есть. Что учесть:

- **База.** Использовать управляемый PostgreSQL платформы: убрать сервис
  `db` и прописать `DB_HOST`/`DB_PORT` от провайдера.
- **Фотографии.** Файловая система на PaaS обычно эфемерная — данные
  теряются при перезапуске. Понадобится либо постоянный диск, если
  платформа его даёт, либо реализация `OneDriveStorage` (или
  S3-совместимого хранилища) в `reports/storage.py`. Интерфейс для этого
  уже готов, меняется только один класс.
- **Бот.** Отдельный always-on процесс. Бесплатные тарифы с усыплением
  не подойдут: усыплённый бот перестаёт получать сообщения.

## Проверочный список после переезда

- [ ] карта открывается, точки на месте
- [ ] фотографии показываются
- [ ] `/admin/` пускает по старому паролю
- [ ] бот отвечает на `/start`, заявка доходит до админки
- [ ] на старом сервере бот остановлен
- [ ] `docker compose exec web python manage.py check --deploy` — чисто
- [ ] cron с бэкапом настроен заново
