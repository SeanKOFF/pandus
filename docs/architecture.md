# Архитектурные решения

## Жизненный цикл точки

`pending` → `published` → `resolved` / `rejected`

- `pending` — прислано ботом, не видно на публичной карте.
- `published` — одобрено модератором, видно на карте **бессрочно**,
  пока статус не сменят вручную.
- `resolved` — проблема устранена, точка остаётся на карте (другим
  цветом), попадает в отчёт для города.
- `rejected` — спам/дубль/не по теме, скрыто, но не удаляется.

Отдельной таблицы "решённых проблем" нет — есть `report_status_history`,
которая через триггер в БД автоматически логирует каждую смену статуса.
Выборка устранённых за период — это представление `v_resolved_log`
(см. `db/schema.sql`).

## Категории

Таблица `categories`, а не enum в коде — новую категорию можно добавить
через админку без деплоя. Стартовый набор: нет пандуса, разбитый
тротуар, перекрыт проезд, прочее.

## Модерация и приватность фото

Модерация — через админ-панель (не через Telegram-канал). Модератор
проверяет фото на приватность (лица, номера) при рассмотрении заявки
вручную, до публикации.

Два кандидата на реализацию админки:
- **Django admin** — почти готово из коробки: списки, фильтры по
  статусу/категории, кнопки-действия, экспорт. Быстрее для MVP.
- **FastAPI + своя админка (React)** — больше контроля над UI, дольше
  в разработке.

## Хранение и раздача фото (OneDrive)

Фото заливаются в OneDrive через Microsoft Graph API. В БД хранится
не прямая ссылка, а `photo_ref` (item id в хранилище) — сама точка не
знает, где физически лежит файл.

Публичная карта получает фото не по прямой ссылке OneDrive, а через
собственный backend-прокси: `GET /media/{report_id}` → backend
запрашивает байты у Graph API и отдаёт их сам. Причины:
- прямые ссылки "поделиться" в OneDrive отдают HTML-превью, а не файл;
- неопубликованные (`pending`) фото никогда не должны быть доступны
  по прямой ссылке;
- при смене хранилища в будущем меняется только один сервис, а не
  все ссылки в базе.

Авторизация к Graph API — delegated OAuth с refresh-токеном,
приложение регистрируется в Azure AD.

## Публичный API / карта

Карта и публичный API работают только с представлением `v_public_map`
(см. `db/schema.sql`) — туда не попадают данные о репортёре, модераторе
и внутренние заметки модерации.
